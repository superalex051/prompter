# M2: Prompter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The prompter screen: smooth mirrored scrolling at 120 Hz, a big mirrored countdown, three scroll modes (speed, finish in,
WPM), a reading line with dimmed text above it, a mirrored HUD (progress + time remaining), touch and hardware-key control, a settings
sheet and app settings, and the screen kept awake.

**Architecture:** All timing and geometry math lives in pure, unit-tested types: `PrompterLayout` (line/paragraph positions extracted
from TextKit), `ScrollEngine` (`@MainActor @Observable` state machine driven by an injected clock and explicit `tick(now:)` calls),
`DisplayPositionSmoother` (eases jumps), `PrompterKeyMap` (HID key → action). The UIKit `PrompterTextView` renders the text with
TextKit and owns a `CADisplayLink` that calls `engine.tick` and sets the content offset every frame (no SwiftUI re-render per frame).
SwiftUI `PrompterScreen` composes the canvas (text + dimming + reading-line markers + HUD + countdown), applies mirror/flip/rotation
to the whole canvas, and handles gestures. Settings UI is a reusable `PrompterSettingsForm`.

**Tech Stack:** SwiftUI, UIKit (UITextView/TextKit, CADisplayLink, UIPress/UIKeyboardHIDUsage), AudioToolbox (system sounds),
Observation, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-06-prompter-design.md` §3.3 (prompter), §3.4 (settings), §6 (ScrollEngine), §7-M2.
**Builds on:** M1 (`docs/superpowers/plans/2026-10-06-m1-library-editor-storage.md`): `Script`, `ScriptStore`, `PrompterSettings`,
`SettingsStore`, `ReadingStats`, `TimeFormatting`, `LaunchOptions`, `LibraryView`, `EditorView`, `PrompterPlaceholderView`.

## Review Focus
1. **Pinch, rotate, settings change or text edit mid-take** → the line at the reading line stays at the reading line (re-anchor by
   character index), the state doesn't change, time remaining is recomputed. *Test:* `ScrollEngineTests.relayoutKeepsAnchorCharacter`.
2. **Display-link hitches / app backgrounded while playing** (a 3 s gap between ticks) → no giant jump; dt is clamped to 0.1 s.
   *Test:* `ScrollEngineTests.largeTickGapIsClamped`.
3. **Finish-in mode after scrubbing back near the deadline** → speed is clamped (no warp-speed scroll); time remaining stays honest.
   *Tests:* `ScrollEngineTests.finishInScrubbedBackLateResumesAtTheChosenPace`, `.finishInPastTheDeadlineResumesAtAReadablePace`.
4. **Empty or one-word script; zero-height layout before the first layout pass** → no division by zero/NaN, Start goes straight to
   finished or waits for layout, HUD shows 0:00. *Tests:* `ScrollEngineTests.emptyLayoutNeverProducesNaN`, `.startBeforeLayoutWaits`.
5. **Commands in odd states** (pause during countdown, resume when idle, step past the end, back to top while playing, speed step at the
   range limits) → well-defined results, never a crash. *Test:* `ScrollEngineTests.commandsInEveryState` (table-driven).

## Engine semantics (authoritative for Tasks 1 and 2)

**Position.** `position` (points) is the y offset into the laid-out text that sits at the reading line. `position = 0`: the top of the
first line is at the reading line. `maxPosition = layout.contentHeight`: all text has passed the reading line. In the text view,
`textContainerInset.top = readingLineY` and `textContainerInset.bottom = canvasHeight - readingLineY`, so
`contentOffset.y = displayPosition` exactly.

**States.** `PlaybackState` (in `Shared/`, Codable, used by the watch in M3): `idle`, `countdown(Int)`, `playing`, `paused`, `finished`.

| Command | idle | countdown(n) | playing | paused | finished |
|---|---|---|---|---|---|
| `start()` | countdown(N) or playing if N = 0 | no-op | no-op | resume | back to top, then like idle |
| `pause()` | no-op | cancel → idle | paused | no-op | no-op |
| `resume()` | start() | no-op | no-op | playing | start() |
| `togglePlay()` | start() | cancel → idle | pause() | resume() | start() |
| `backToTop()` | position 0, idle | idle, position 0 | idle, position 0 | idle, position 0 | idle, position 0 |
| `stepLine(±1)`, `stepParagraph(±1)`, `jumpBack()` | move | move | move, keep playing | move | move → paused (if before end) |
| `scrubBegan()` / `scrub(by:)` | move | cancel → idle, move | pause, move | move | → paused, move |

`N = settings.countdownSeconds`. Countdown: `countdownEnd = now + N`; each tick, `n = ceil(countdownEnd - now)`; when n changes the
state becomes `.countdown(n)` and the event `.countdownTick(n)` fires (the first digit fires on `start()`); when `now >= countdownEnd`
the state becomes `.playing`, `.go` fires, and scrolling starts from that instant. If the layout is empty (`contentHeight == 0`) when
`start()` is called, the engine stays idle with `pendingStart = true` and starts when a non-empty layout arrives.

**Ticks.** `tick(now:)` while playing: `dt = min(now - lastTick, 0.1)`, `position += speed * dt`, finish-in budget `-= dt`.
`position >= maxPosition` → `position = maxPosition`, `.finished` state, `.finished` event.

**Speed (points per second)**, with `pitch = layout.averageLinePitch` (contentHeight / lineCount; 1 if no lines):
- `.speed`: `speedLevel * 0.25 * pitch` (level 1–10, so 0.25–2.5 lines per second; it stays proportional when the font changes).
- `.wpm`: `wordsPerMinute / 60 * contentHeight / max(wordCount, 1)` (constant pace; the whole script takes wordCount / wpm minutes).
- `.finishIn`: `remainingDistance / max(budget, 0.001)`, clamped to `maxFinishInSpeed = 2.5 * pitch` per second (the fastest
  speed-mode level). `budget` is set on `start()` from idle/finished to `finishInSeconds * (1 - position / maxPosition)`, decreases
  only while playing, is unchanged by scrubs and steps (so speed recalculates), and is reset to `finishInSeconds` by `backToTop()`.
  Whenever playing begins (start, "go" after the countdown, resume), a budget the rest can't be read in at the cap (the deadline
  passed, or a scrub went back late) is replaced by `max(finishInSeconds * remainingDistance / contentHeight, remainingDistance /
  maxFinishInSpeed)`: the pace the take was set up for, never faster than the cap. While counting down or paused the HUD already
  shows that replacement budget (`ScrollTiming.readableBudget`).

**Time remaining** (`remainingSeconds`, Double, ≥ 0): `.speed`/`.wpm`: `(maxPosition - position) / speed`;
`.finishIn`: `max(budget, remainingDistance / maxFinishInSpeed)`. HUD shows `TimeFormatting.clock(ceil(remainingSeconds))`.

**Speed steps** (`speedStep(_ n: Int)`; the watch Crown sends ±1 per detent, buttons/keys send ±5):
`.speed`: level ± 0.1·n (1…10). `.wpm`: wpm ± 2·n (60…300). `.finishIn`: finishInSeconds ∓ 5·n (10…7200; plus = faster = shorter),
and `budget *= new / old`. `setSpeed(Double)` sets the active mode's value directly (level, wpm or seconds), clamped.
`speedLabel`: `.speed` → "Speed 3.0", `.wpm` → "140 wpm", `.finishIn` → "Finish in 5:00".

**Steps.** `stepLine(+1)`: first line start `> position + 0.5`, else `maxPosition`. `stepLine(-1)`: last line start `< position - 0.5`,
else 0. Paragraph steps use only lines with `startsParagraph`. `jumpBack()`: last paragraph start `<= position - 0.5 * pitch`, else 0
(so pressing it just after a paragraph begins goes to the previous paragraph).

**Relayout.** `updateLayout(_ new: PrompterLayout)`: record `anchor = old.characterIndex(at: position)` first (if the old layout had
lines), then `position = new.position(ofCharacterIndex: anchor)`, clamped; state unchanged.

**Observation budget.** `position` is `@ObservationIgnored` (the text view reads it every frame). `progress` (0…1, rounded to 0.001),
`remainingSeconds` (rounded to whole seconds for observation, keep the precise value internally), `state` and `speedLabel` are observed and
only assigned when their value actually changes, so SwiftUI re-renders the HUD at most a few times per second.

**Interfaces:**
```swift
// Shared/PlaybackState.swift
enum PlaybackState: Codable, Equatable, Hashable, Sendable { case idle, countdown(Int), playing, paused, finished }

// PrompterLayout.swift
struct PrompterLayout: Equatable, Sendable {
    struct Line: Equatable, Sendable {
        var y: Double                 // top of the line fragment, relative to the top of the text (first line y = 0)
        var height: Double
        var characterIndex: Int       // UTF-16 offset of the first character of the line
        var startsParagraph: Bool
    }
    var lines: [Line]                 // document order, y ascending
    var contentHeight: Double         // height of all laid-out text
    var wordCount: Int
    static let empty: PrompterLayout
    var averageLinePitch: Double { get }                 // contentHeight / lines.count, or 1 when empty
    func lineIndex(at position: Double) -> Int?          // line containing position (clamped to first/last); nil if no lines
    func characterIndex(at position: Double) -> Int      // first character of lineIndex(at:), 0 if none
    func position(ofCharacterIndex index: Int) -> Double // y of the line containing that character (clamped)
}

// DisplayPositionSmoother.swift
struct DisplayPositionSmoother: Sendable {
    var current: Double
    /// Within `snapDistance` (default 24 pt) of the target → returns the target exactly (normal scrolling is untouched).
    /// Otherwise eases: current += (target - current) * (1 - exp(-dt / 0.09)).
    mutating func next(target: Double, dt: Double) -> Double
}

// PrompterKeyMap.swift (import UIKit)
enum PrompterKeyAction: Equatable, Sendable { case togglePlay, stepLine(Int), stepParagraph(Int), speedStep(Int), backToTop, exit }
enum PrompterKeyMap {
    /// Space, Return, keypad Enter → togglePlay. Down/Right/PageDown → stepLine(+1) (Shift: stepParagraph(+1)).
    /// Up/Left/PageUp → stepLine(-1) (Shift: stepParagraph(-1)). "=" / Shift-"=" / keypad + → speedStep(+5).
    /// "-" / keypad - → speedStep(-5). "0" / keypad 0 → backToTop. Escape → exit. Anything else → nil.
    static func action(for usage: UIKeyboardHIDUsage, shift: Bool) -> PrompterKeyAction?
}

// ScrollEngine.swift
@MainActor @Observable
final class ScrollEngine {
    enum Event: Equatable, Sendable { case countdownTick(Int), go, paused, resumed, finished, jumped }

    init(settings: PrompterSettings, now: @escaping () -> TimeInterval = { CACurrentMediaTime() })
    var settings: PrompterSettings          // mode/speed/wpm/finishIn/countdown; speed steps write back here
    private(set) var state: PlaybackState
    private(set) var layout: PrompterLayout
    @ObservationIgnored private(set) var position: Double
    private(set) var progress: Double        // 0…1
    private(set) var remainingSeconds: Double
    private(set) var speedLabel: String
    var pointsPerSecond: Double { get }      // current speed per the rules above
    @ObservationIgnored var onEvent: ((Event) -> Void)?
    var needsFrames: Bool { get }            // true while countdown or playing (the view pauses its display link otherwise)

    func updateLayout(_ layout: PrompterLayout)
    func start(); func pause(); func resume(); func togglePlay(); func backToTop()
    func stepLine(_ direction: Int); func stepParagraph(_ direction: Int); func jumpBack()
    func speedStep(_ n: Int); func setSpeed(_ value: Double)
    func scrubBegan(); func scrub(by delta: Double)
    func tick(now: TimeInterval)
}
```

**Tests (write first; use a `ManualClock` class in the test file whose `now` you advance):**
- Layout: lineIndex/characterIndex/position(ofCharacterIndex:) on a hand-built 5-line layout incl. clamping and empty layout.
- Engine: countdown 5 → digits 5,4,3,2,1 fire once each, then `.go` and `.playing`; countdown 0 → playing immediately; pause during
  countdown → idle; `.speed` level 4 with pitch 100 → 100 pt/s, after 2 s position 200; `.wpm` 140 with 140 words over 1400 pt → finishes
  at t = 60 s ±0.1; `.finishIn` 120 s from top → finished at 120 s ±0.1; after scrubbing back 50 % at t = 60 s the new speed is
  remainingDistance / 60; `finishInSpeedIsClampedWhenBudgetIsTiny`; time remaining per mode; pause stops position and budget;
  `largeTickGapIsClamped`; stepLine/stepParagraph/jumpBack targets incl. ends; backToTop resets state and budget;
  speedStep per mode and clamping (level stays in 1…10, wpm 60…300); speedLabel strings; `relayoutKeepsAnchorCharacter`;
  `emptyLayoutNeverProducesNaN`; `startBeforeLayoutWaits`; `commandsInEveryState` (table over states × commands, asserting the table above);
  `progress` and `remainingSeconds` are not re-assigned when unchanged (observe with `withObservationTracking`, expect no change fired
  for a tick that doesn't change the rounded values).
- Smoother: snaps within 24 pt; eases a 1000 pt jump to within 1 pt in < 0.6 s of 1/120 s steps; never overshoots.
- Key map: every mapping in the comment above, and an unmapped key → nil.

**Steps:** tests → implement → `scripts/build.sh` + `scripts/test.sh` green → commit "M2: scroll engine, layout, key map".

**Behaviour:**
- Full screen: `.statusBarHidden()`, `.persistentSystemOverlays(.hidden)`, `UIApplication.shared.isIdleTimerDisabled = true` while
  visible (restore on disappear), background = scheme background, `.ignoresSafeArea()`.
- Canvas transform: rotation (for 90/270 the canvas frame swaps width and height, then `rotationEffect`), then
  `scaleEffect(x: mirror ? -1 : 1, y: flip ? -1 : 1)`. Gestures are attached INSIDE the transformed canvas so drag directions follow
  the finger on the glass and on the screen.
- Typography from settings: `UIFont.systemFont(ofSize:weight:)`, paragraph `lineHeightMultiple = lineSpacing`, paragraph spacing ≈ 0.5 ×
  font size, side insets = `sideMargin × width`, colours from `scheme` (white/black, yellow #FFD60A/black, black/white).
  On iPad scale the default 72 pt by `min(width, height) / 402` (iPhone 17 Pro landscape height) so text fills a similar share.
- Reading line at `readingLinePosition × height`: small amber chevron markers at both side margins; everything above it is covered by
  the background colour at `1 - dimmedOpacity` alpha with a 24 pt feathered edge.
- HUD (inside the canvas, bottom edge, small): 3 pt progress bar across the width + time remaining (`m:ss`) + state word
  ("Ready", "Paused", "End"; nothing while playing) + speed label. Reads `engine.progress`, `remainingSeconds`, `state`, `speedLabel`.
- Countdown: huge centred digit (≈ 60 % of the canvas height, heavy, rounded), mirrored with the canvas.
- Touch: tap → `togglePlay`; drag → `scrubBegan` + `scrub(by: -translationDelta)` (text follows the finger); pinch → font size
  (24…200, live, persisted via SettingsStore at the end of the gesture) with relayout anchored by the engine; long-press (0.5 s) OR a
  two-finger tap → pause + settings sheet (the sample script promises both; a `UITapGestureRecognizer(numberOfTouchesRequired: 2)` in
  the UIKit view is fine if SwiftUI can't express it — make sure a one-finger tap still toggles play and a two-finger tap does not). Close button: `xmark.circle.fill`, top-leading in PHYSICAL coordinates (outside the transform), visible while
  not playing and for 3 s after any touch.
- Keys: `PrompterKeyAction` → engine; `.exit` dismisses. Re-become first responder after the settings sheet closes.
- Settings sheet: `PrompterSettingsSheet` (Task 3); edits apply live (relayout + engine.settings) and persist via `SettingsStore`.
  Engine speed changes (keys, later the watch) persist back to `SettingsStore` too.
- Script text changes while open are not expected; read the script once on appear.

**Steps:** implement → `scripts/build.sh` + `scripts/test.sh` green → run on the iPhone 17 Pro simulator in landscape
