# M4: Stretch (voice-follow, markup, PDF import, App Intents, iPad, release readiness) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The "should" features from the research doc, plus everything needed so the owner can upload the build to TestFlight the next morning
(on the owner's existing Apple developer team) and install it on their iPhone and watch.

**Architecture:** Each feature keeps its logic in pure, unit-tested types (`ScriptMarkup`, `VoiceAligner`, `PDFTextExtractor` wrapper)
and plugs into the existing seams: `ReadingStats` (timed words), `PrompterText` (attributed string building), `ScrollEngine` (a new
voice-follow target), `ScriptImporter` (PDF), `PrompterRemoteHub` (App Intents act on the active prompter like the watch does).

**Spec:** `docs/superpowers/specs/2026-10-06-prompter-design.md` §7-M4; research doc "Milestone 4, stretch (should)".

## Global Constraints
- Same as M1–M3: iOS 26+, Swift 6 strict concurrency, Apple frameworks only, XcodeGen (Info.plist keys and entitlements via
  `project.yml`), Swift Testing, Maestro flows for every UI change (`qa/`, `scripts/qa.sh`), screenshots looked at.
- Voice-follow is opt-in (a scroll mode); nothing asks for the microphone until the user picks it.
- No signing changes overnight (AGENTS.md). `DEVELOPMENT_TEAM` stays empty; the morning checklist sets it.

## Review Focus
1. **Markup that looks like markup but isn't** (a URL with `//`, "[pause] for effect" mid-sentence, `// ` inside a line) → only whole
   lines are cues/notes; mid-line text is read as script. *Test:* `ScriptMarkupTests.onlyWholeLinesAreMarkup`.
2. **Voice-follow when the speaker ad-libs, repeats a line or skips a paragraph** → the cursor never jumps backwards on a repeated common
   word, catches up on a skip within a bounded window, and holds still on ad-libs. *Tests:* `VoiceAlignerTests.adLibHoldsPosition`,
   `.repeatedWordDoesNotJumpBack`, `.skipAheadWithinWindow`.
3. **Permission denied / on-device recognition unavailable** → voice mode says so in plain words and falls back to WPM; no crash, no
   silent nothing. *Test:* `VoiceFollowControllerTests.deniedFallsBackToWPM` (with a fake recognizer).
4. **Scanned PDF with no text layer** → "This PDF has no text to import (it may be a scan)." not an empty script. *Test:*
   `ScriptImporterTests.pdfWithoutTextIsEmpty`.
5. **App Intent with no prompter open** → a spoken/visible "Open a script in Prompter first." rather than a silent success. *Test:*
   `PrompterIntentsTests.startWithoutPrompterExplains`.

### Task 1: Script markup (`[pause]` cues, `// notes`)  · Opus (touches the prompter text builder)
- `Prompter/Models/ScriptMarkup.swift`: `enum ScriptLineKind { case text, note, pause }`; `ScriptMarkup.lines(of body) -> [(range, kind)]`.
  A line whose trimmed text starts with `//` is a note; a line that is exactly `[pause]` (case-insensitive, optional seconds
  `[pause 3]`) is a pause cue. Everything else is text.
- `ReadingStats` counts only text lines (so library/editor read times and WPM timing ignore notes and cues). Editor footer unchanged.
- Prompter rendering: notes in the same font at 55 % size, italic, 45 % opacity; pause cues as a centred amber "PAUSE" capsule line.
  The engine's WPM speed uses timed words only.
- Optional auto-hold: `[pause 3]` holds scrolling for 3 s when it reaches the reading line (setting "Hold at [pause] cues", default on
  only when a duration is given). Engine test for the hold.
- Sample script gets one note line and one `[pause]` line demonstrating the syntax.

### Task 2: PDF import  · Sonnet
- `ScriptImporter`: `.pdf` via PDFKit `PDFDocument(url:)` → page strings joined with blank lines → `normalize`. Hyphenated line-end
  breaks ("exam-\nple") rejoined; repeated page headers/footers are out of scope. Empty text → `.empty` with the scan message.
- `.fileImporter` allows `.pdf`. Tests build a PDF in-test with `UIGraphicsPDFRenderer` (text) and an image-only one.

### Task 3: App Intents  · Sonnet (with Opus review)
- `StartPrompterIntent`, `PausePrompterIntent`, `ResumePrompterIntent` (`openAppWhenRun = true`), acting through
  `PrompterRemoteHub.handle(_:)` on the active prompter; no prompter → `IntentResult` with dialog "Open a script in Prompter first."
- `PrompterShortcuts: AppShortcutsProvider` with phrases "Start \(.applicationName)", "Pause \(.applicationName)",
  "Resume \(.applicationName)". Unit tests call `perform()` against a hub with a fake/real engine.

### Task 4: Voice-follow  · Opus
- `Prompter/Features/Prompter/Voice/VoiceAligner.swift` (pure): script word index (normalised tokens with UTF-16 offsets, timed lines
  only) + `mutating func advance(with recognizedWords: [String]) -> Int?` returning the script word index of the latest confident match.
  Local alignment of the last ~6 recognised words against a window of [cursor - 5, cursor + 60] script words, fuzzy word equality
  (case/punctuation-insensitive, edit-distance ratio ≥ 0.75, number words ↔ digits), monotonic unless 3+ consecutive matches agree
  further back. Thoroughly tested with scripted transcripts (ad-lib, skip, repeat, stutter, partial-result rewrites).
- `VoiceFollowController` (`@MainActor`): `SFSpeechRecognizer` with `requiresOnDeviceRecognition = true` (check
  `supportsOnDeviceRecognition`), `AVAudioEngine` input tap, restarts the task on final results/errors, publishes `isListening`,
  `lastHeard`, and the matched character index. Behind a protocol so tests use a fake.
  (If iOS 26's `SpeechAnalyzer`/`SpeechTranscriber` is available and simpler for long-form, it may be used instead; justify in the report.)
- `ScrollMode.voice` (tolerant decoding keeps older settings valid): the engine's target = layout position of the matched word's line;
  position eases toward it at ≤ 4 lines/s; no new match for 2 s → holds (HUD shows "Listening…"); voice mode ignores WPM/time math for
  movement but time remaining is estimated from remaining words at 140 wpm.
- `project.yml`: `NSMicrophoneUsageDescription` = "Prompter listens to your voice so the script follows you as you speak. Audio stays on
  this iPhone.", `NSSpeechRecognitionUsageDescription` = "Speech is recognised on this iPhone to keep the script in step with you."
- Settings form: Mode picker gains "Voice"; footer explains on-device listening. Simulator can't really be spoken to overnight → the
  report lists exactly what the owner should try on the device (Needs the owner).

**Task 4 as built (2026-10-07):**
- API: SpeechAnalyzer + SpeechTranscriber (`.volatileResults` + `.fastResults`) first, SFSpeechRecognizer on-device as the
  fallback where SpeechTranscriber isn't available or its model can't be downloaded (`SpeechRecognizerChoice`).
  Measured on the Mac with real-time streaming: volatile results about once a second with no backlog (without
  `.fastResults` only every ~3.8 s); no permission prompt beyond the microphone; no task limits to restart around.
- Neither recogniser works on the simulator (SpeechTranscriber unavailable, DictationTranscriber "Model not available",
  SFSpeechRecognizer `kLSRErrorDomain 300`). So: `scripts/voice-check.sh` runs the app's own voice code against a spoken
  read-through on the Mac, and `scripts/voice-demo.sh` replays those recorded results in the simulator (`-voiceReplay`).
- Aligner rules beyond the plan: "reading on" (a match straight after already-read text) is accepted whatever the word;
  a lone common word after stray words is not; a backward move needs a second update to agree (a recogniser taking back
  its last words for a moment looked like a re-read); after a move by hand the source forgets what it heard
  (`SpeechSource.forgetHeard()`), or words from before a step back pulled the text forward again.
- Target = the line of the next word to read, so the next line comes up as the last word of a line is heard.
